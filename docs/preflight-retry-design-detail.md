# 预检持续失败后的退避与交接：详细设计

[主文档](preflight-retry-design.md)定义本期范围。本文件包含待实现的接入方案，不代表线上行为已经改变。

已实现 `internal/preflight` 的独立账本、调用前持久化、并发排他、退避、耗尽和带原因的恢复记录；尚无生产调用方。当前未结算记录一律阻止再次 Begin，不提供自动推断进程死亡的能力。已增加只读调用专用的 observation checkpoint 能力，记录 caller/run/native session 并继承进程锁，禁止覆盖已有记录和用于开发续跑。该能力尚未绑定到预检账本；真实终态核对、两个调度入口、CLI 恢复及面板呈现仍待实现。

## 已确认的证据

2026-11-03 本地修复版提交 `7d9fc76c` 的协调调用 `e09c2952d96db4158b3cfe045b97e7c2` 在 45 秒后取消，原生会话 `bc7c1434-cc74-4969-916a-f3a7bf044051` 没有 assistant 结果。扫描进程退出码为 0，不是开发核验成功。此前验收计划调用 `43990c253da174e3482873bbdd1e9ccd` 的原生记录显示 HTTP 502 和 9 次重试，最终状态为 error。两者是不同调用，不能把前者的超时直接归因于 502。

`dispatchCoordination` 失败时发布 waiting 队列状态，但不持久化失败次数；`run.go` 和 `coordinator_jobs.go` 都跳过当前任务。协调门禁在修复预算预留之前，所以不能指望修复账本约束这条路径。`prepareImplementationPlan` 也是入队前的外部调用，应纳入同一次完整预检的故障管理，避免只修协调入口后把循环转移到计划生成。

现有 `internal/repairledger` 使用 MaxInfra=5、Cooldown=5 分钟、MaxBackoff=1 小时。本方案复用策略数值，使用独立账本，不向现有修复账本写入或释放预留。

## 状态与持久化

预算以仓库和 issue 为稳定身份；任务操作、目标 PR/head、快照摘要、失败阶段作为每次事件的证据，不用可变摘要重建预算。跨扫描、进程重启、PR/head 和评论变化保留连续故障历史。成功是同一次完整预检通过协调、计划生成和入队前事实复核，不能仅凭协调返回 proceed 清零。

在已有仓库/协调锁保护下，发起外部预检前持久化一次尝试的身份、起始时间和阶段，再调用模型或远端。完成时追加成功、技术失败或无故障等待的终态。写入失败必须停止调用；损坏或未知版本账本必须阻止新调用并给出诊断，不得按空账本继续。

前次尝试未终结时，先确认同一执行是否仍活动。活动或归属不明不能启动重复调用；确定终止后将其作为中断故障计入，而非删除记录。不能仅依据心跳消失或 PID 数字判断可重试，需要现有执行身份和存活依据。若预检目前没有足够的持久执行身份，应先补证据再开放自动恢复。

冷却期内无需调用模型；公布明确 next_retry_at。连续技术失败达到 5 次后，公布 blocked 和恢复说明，停止此任务的自动预检。正常依赖等待、已有任务、锁忙、明确取消整个调度回合不应伪装成模型故障；成功返回但格式或引用校验失败仍属于预检技术失败。快照变化属于重新取证，不应沿用旧批准；需单独限制其重试频率，不能无限忙转。

## 人工恢复与可见性

提供明确、带原因的恢复入口；恢复创建可审计的新一轮，保留旧轮失败和操作者。禁止通过编辑账本、清标签、issue 评论或新 head 隐式重置预算。恢复也不能覆盖活动调用或改变代码修复次数。具体命令和字段在实现时沿用现有 CLI 组织方式，不在文档中宣称尚不存在的命令可用。

队列与任务详情应给出阶段、次数/上限、最近失败类别、下一次重试时间，耗尽时给出停止原因和处理人。错误正文可能包含敏感请求信息，展示稳定分类和诊断引用，原始证据按现有私有存储规则保留。发布状态失败不能被忽略成已完成交接。

## 验收要求

- 用隔离 HOME 的无 GUI 测试验证连续故障、退避时间、达到上限后零新增外部调用，以及完整成功后的下一轮。
- 重载持久状态后次数和冷却不变；变更 head、评论和操作不会恢复预算；损坏账本失败关闭。
- 保留中断调用身份；存在活动执行时不重派，确定终止后只结算一次。
- 本地调试入口和 controller 入队入口共用同一策略；协调成功但计划生成失败仍递增同一轮故障。
- 正常依赖等待、锁竞争、已有活动任务不耗尽故障预算；快照过期不能复用批准。
- 验证代码修复账本字节不变，既有 CI、来源、验收和部署门禁不被绕过。
- 人工恢复留下原因和历史，活动调用期间恢复被拒绝；恢复不得产生并发执行。
- 面板只读状态证据和真实故障交接分别验收。单元测试通过不等于已部署或已完成连续一周 20 个任务的目标。
