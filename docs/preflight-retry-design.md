# 预检持续失败后的退避与交接

状态：已实现独立预算账本并通过针对性测试；已接入本地与 controller 派发入口，执行身份终态核对和恢复命令尚未完成，未部署、未通过运行验收。

开发任务开始前，协调判断和验收计划生成都可能遇到模型服务故障。现在协调请求单次会超时，但下一次扫描仍可重新请求，持续故障缺少累计上限。目标是让任务明确显示等待原因、下一次重试时间和耗尽后的处理人，避免无限消耗请求。

本期在同仓库任务的预检入口增加独立、持久化的故障预算。沿用现有修复基础设施策略的数值：最多 5 次，首次退避 5 分钟，随后递增，最长 1 小时。该预算不占用、重置或替代代码修复预算。正常等待依赖、已有活动任务和锁竞争不算故障。

达到上限后停止该任务的自动预检，保留失败记录并提示人工处理；其他任务与自动调度继续运行。恢复必须通过明确的恢复操作并记录原因，评论变化、PR 更新和服务重启都不能悄悄恢复预算。一次完整预检成功结束本轮连续故障。

先实现预算与重启恢复，再接入协调和计划生成入口，最后核验面板状态和真实故障交接。保持当前完成标记、profile、超时以及 CI、开发来源、独立验收和部署门禁。
