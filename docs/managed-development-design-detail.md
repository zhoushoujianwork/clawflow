# 本机无人值守开发闭环：实现与验收

返回[主设计](managed-development-design.md)。本文约束本期范围，不重复定义执行协议；状态机和部署恢复以[可恢复执行设计](resilient-execution-design.md)及[worker runbook](resilient-execution-runbook.md)为准。

## 执行与恢复

单 controller 是当前调度权威。独立 worker 的执行所有权、attempt 和恢复能力必须核实；heartbeat 丢失不构成重新派发授权。恢复时保留 worktree、journal、Offload session 来源和实际结果，禁止通过清空记录或重置预算制造成功。

部署前检查活跃任务与已部署协议。源码支持持久执行不代表旧进程已完成迁移；首次切换 legacy embedded worker 必须排空。后续升级遵循[controller 升级说明](controller-upgrade.md)，不得增加共享并发容量或重复启动调度器。

## 失败处理

| 情况 | 处理边界 |
| --- | --- |
| 可信、结构完整的代码缺陷证据 | 在权限和剩余预算内修复，然后重新检查 |
| CI 基础设施或执行环境故障 | 定位环境原因，不能将其直接当成实现缺陷 |
| 验收报告结构无效、校验失败 | 交由验收侧处理，不授权代码修复或合并 |
| 缺少验收环境或证据 | 明确记录缺失内容，不伪造通过 |
| 范围或产品决策不明确 | 请求用户决策，保留当前结果 |
| 修复预算耗尽 | 保留阻塞及尝试记录，不自动重置 |

CI 状态只由可信的 CI 查询确定；日志与评论是诊断输入，不能替代状态。独立验收检查行为，开发来源检查实际执行记录，部署记录说明线上版本；不能混成一个循环依赖的门禁。

## 证据与界面

记录实际任务、session、run、退出状态、head SHA 和产物位置。开发无改动也需如实记录，不能虚构提交。验收只能对所检查的版本作结论；合并和部署分别确认结果。

原生 App 展示任务阶段、worker、排队或阻塞原因，以及当前 attempt 的持续时间。断连或快照过期时停止实时动画和计时增长，保留最后已知状态。执行成功不能显示成 CI、验收、合并全部完成。

## 存储与发布

当前部署使用 PostgreSQL。存储迁移独立验收，不能将迁移草案描述为线上能力。候选版本隔离参照[候选版本说明](candidate-isolation.md)；App 安装与服务可执行文件升级分开，服务升级需要真实运行证据。

## 验收矩阵

| 链路 | 必需证据 |
| --- | --- |
| 正常交付 | 真实 Issue、开发记录、同一 head 的 CI 与独立验收、最终 PR 状态 |
| CI 修复 | 真实失败、有限修复记录、修复后的 CI 与验收 |
| 验收修复 | 有效缺陷报告、修复来源、复验；无效报告不触发代码修复 |
| 重启恢复 | 所有权与部署协议、不中断或安全恢复记录、无重复执行 |
| 持续运行 | 一周且至少 20 个真实任务，成功、阻塞、人工介入和恢复统计 |

未执行或证据不足的检查保持 pending/blocked。以[部署观察记录](unattended-deployment-2026-11-02.md)作为现有证据入口，不在本设计中固定容易过期的安装版本。
